# Transaction History

- **Status:** Approved
- **Date:** 2026-10-27
- **Version target:** v0.4.0

## Context

The dashboard shows the five most recent transactions and a disabled "View all transactions" link. This stage adds the full history with server-side filtering, search, pagination and CSV export, and closes the minor findings deferred from v0.3.0.

## Goals

- List every transaction, ten per page, newest first.
- Filter by account, type and date range, and search by description.
- Keep filters and page in the URL so views survive reloads and can be shared.
- Export all matching transactions to CSV safely.
- Share one application layout and navigation between the dashboard and the history page.

## Non-goals

- Transaction details page.
- Infinite scroll or "Load more".
- Sorting by columns other than date.

## API contract

### `GET /api/transactions`

| Parameter | Type | Default | Rule |
| --- | --- | --- | --- |
| `accountId` | string | none | Unknown account returns an empty page |
| `type` | `credit` \| `debit` | none | Any other value is ignored |
| `from` | `YYYY-MM-DD` | none | Inclusive; invalid format is ignored |
| `to` | `YYYY-MM-DD` | none | Inclusive; invalid format is ignored |
| `q` | string | none | Trimmed; matches the description ignoring case and accents |
| `page` | integer ≥ 1 | 1 | Invalid values use the default; a page beyond the last returns an empty list |
| `pageSize` | integer 1–50 | 10 | Invalid values use the default; values above 50 are capped |

If both dates are valid and `from` is after `to`, the response is `400 VALIDATION_ERROR` with the message "The start date must be before the end date."

Response:

```ts
interface TransactionPage {
  transactions: Transaction[];
  page: number;
  pageSize: number;
  total: number;
  totalPages: number;
}
```

`totalPages` is at least 1. The `limit` parameter from v0.3.0 is removed; the dashboard requests `pageSize=5`.

### `GET /api/transactions/export`

Accepts the same filters except `page` and `pageSize`, and returns every matching transaction as `text/csv` with `Content-Disposition: attachment; filename="altura-transactions-YYYY-MM-DD.csv"`.

| Column | Example |
| --- | --- |
| Date | `2026-10-27 14:05` |
| Description | `Supermercado Nacional` |
| Account | `**** 9874` |
| Type | `Debit` |
| Amount | `-3245.80` |
| Currency | `DOP` |

- Values containing commas, quotes or line breaks are quoted, with inner quotes doubled.
- Cells starting with `=`, `+`, `-`, `@`, tab or carriage return are prefixed with `'` to prevent formula execution in spreadsheet apps. Signed amounts are written as numbers and are exempt, because they are generated by the server.

### Time zone

Dates are filtered and displayed in the bank's time zone, `America/Santo_Domingo` (UTC−4, no daylight saving). A transaction at 23:30 on October 26 in Santo Domingo belongs to October 26 regardless of the viewer's time zone.

```
├── utils/
│   ├── dates.ts                    Bank time zone helpers
│   └── download.ts                 Save a Blob as a file

```

| Unit | Responsibility |
| --- | --- |
| `transactionQuery.ts` | Pure functions used by the mock handlers: `filterTransactions`, `paginate`, `toCsv` |
| `useTransactionFilters` | Single source of truth for filters and page, backed by `useSearchParams`; changing any filter resets the page to 1 |
| `TransactionsPage` | Wires filters, the page query (with previous data kept while loading) and export |
| `AppLayout` | Layout route element wrapping every private page |

## UI

- **Navigation:** "Dashboard" and "Transactions" links in the header, with `aria-current="page"` on the active one. The balance toggle remains on the dashboard; its preference also applies to the history.
- **Filters:** account select ("All accounts" plus each account by label and masked number), type select ("All types", "Credits", "Debits"), "From" and "To" date inputs, search input labeled "Search transactions" with a 300 ms debounce, and a "Clear filters" button shown when any filter is active.
- **List:** columns Date, Description, Account, Amount; credits in green with `+`, debits with `−`; visually hidden "Credit" or "Debit".
- **Pagination:** summary "Showing 11–20 of 30 transactions", "Previous" and "Next" buttons disabled at the edges, and page number buttons with `aria-current="page"` inside `<nav aria-label="Pagination">`. Changing page moves focus to the list heading.
- **States:** skeleton rows with `aria-busy="true"` on the list region while loading; "We couldn't load your transactions." with "Try again"; "No transactions match your filters." with "Clear filters"; previous page stays visible while the next one loads.
- **Export:** "Export CSV" button, disabled while exporting, exports the current filters and shows "Export failed. Please try again." on error.
- **Dashboard:** "View all transactions" becomes a link to `/transactions`.
